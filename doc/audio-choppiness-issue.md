# Audio Choppiness & Low FPS Issue

## Symptoms

- Sound is choppy during gameplay
- Actual FPS is lower than the target 60 FPS
- The `start_snes.sh` script runs the FCEUmm core with Contra (USA).nes

## Root Cause: Missing Frame Throttle

The main loop in `rustsdlretro-frontend/src/main.rs` runs without any frame pacing (throttle). Without the throttle, the main loop spins as fast as possible — producing **4000+ FPS** on this hardware.

### How It Causes Choppy Audio

Audio samples are generated by the libretro core **once per `retro_run` call**, which happens once per main loop iteration. The ring buffer is drained by a background ALSA thread at a fixed rate (48000 Hz).

| State | Effect |
|-------|--------|
| **No throttle** (4000+ FPS) | Core runs 4000+ frames/sec → audio samples produced 4000+ times/sec → ring buffer overflows → oldest samples dropped → audio choppiness |
| **With throttle** (~60 FPS) | Core runs ~60 frames/sec → audio samples produced ~60 times/sec → ring buffer stays filled → smooth audio |

The throttle ensures the main loop runs at the game's target FPS (60.10 FPS for NES), so audio samples are produced at the correct rate and the ring buffer stays filled.

## Evidence

### Without throttle (disabled in main.rs):
```

```

### With throttle (restored):


## Key Code Locations

- **Throttle logic**: `rustsdlretro-core/src/lib.rs` — `Throttle` struct, `check_wait()`, `skip_check()`
- **Main loop**: `rustsdlretro-frontend/src/main.rs` — `throttle.check_wait()` call and sleep loop
- **Audio ring buffer**: `rustsdlretro-core/src/audio.rs` — `RingBuffer` (capacity 65536 samples)
- **Audio callbacks**: `rustsdlretro-core/src/lib.rs` — `audio_sample_cb`, `audio_sample_batch_cb`

## Current Status

The throttle has been re-enabled. FPS is now stable at ~58.6-58.8 (close to the 60.10 target). Audio should now be smooth.
